시장 현황과 날짜별 종합 탐색은 KPI·요약이 반복됐다. 항로와 통항을 별도 메뉴로 읽으면 같은 기간을 다시 선택해야 했다. 상태 분포/지속 막대는 분류 자체를 보여주지만 같은 상태의 환경 차이를 설명하기 어려웠다. 예측의 큰 표와 유사 막대는 언제 크게 틀렸는지 드러내지 못했다.

전체 기능의 KEEP/MERGE/REDESIGN/REMOVE 근거는 `C_V2_FEATURE_AUDIT.md`에 있다. 기존 기능이라는 이유로 모두 보존하지 않았고, 원 연구 자료는 삭제하지 않았다.

독립 항로 메뉴는 시장 변화에, 상태 타임라인과 통항은 통합 탐색에 옮겼다. 종합 시점 탐색 메뉴, 반복 KPI, 상태 분포/지속 막대, 중복 모형 막대, 이전/다음 발표 버튼과 오래된 6메뉴 테스트를 제거했다. 직접 날짜 입력·타임라인·A/B 선택으로 날짜 이동을 대체했다. 9상태 관측수·62구간·53전환과 11모형 상세는 펼침 및 CSV로 보존했다.

기간 선택, 13항로, KCCI/SCFI/CCFI, EUMED, 네 통항 경로, 결측/미배정 사유, 실제값·예측 비교, 확대·툴팁·CSV·필터 복원을 유지했다. 중요한 연구 기능이 사라졌는지는 새 사용자 흐름의 회귀로 검사했다.

## 5. 다섯 고도화와 실제 계산

**규칙 기반 시장 해석.** 사용 지표·공식·날짜·조건·원 자료와 연결한 관찰 문장을 제공한다. LLM 원인 추정이나 임의 위험등급은 없다. 미배정 대표상태와 계산 가능한 부분 운임축을 구분한다.

**항로 격차.** 선택 항로가 공통으로 관측된 시작/끝만 비교하고 기준값을 100으로 환산한다. 결측·0분모·공통 관측 1회는 계산 불가로 표시한다. 기본 세 항로의 실제 공통 2025-11-10~2026-11-09에서 KNEI +53.3825%, KMDI +52.1122%, KUWI +235.5114%, 격차 183.3992%p다. 선택 항로 집합에 한정된 수치다.

**동일 상태 A/B.** 같은 대표상태의 완전 발표일만 선택한다. 같은 저운임·횡보 사례끼리도 KCCI 수준과 희망봉 직전7일 평균이 다름을 보여준다. 개별 원값은 내부 근거 파일로 확인한다. 같은 라벨을 같은 미래 결과나 기업 수익성의 근거로 사용하지 않는다.

**운임·통항 동시 탐색.** 단위가 다른 차트를 분리하고 커서와 확대 범위를 연결한다. 주간은 실제 발표일 합집합에 스냅하고, 일별은 관측 없는 운임 날짜를 명시한다. 다른 날짜의 값을 보간하지 않는다. 발표일과 직전7일 관측창을 모두 표시한다. 그래프 좌표는 UTC 자정으로 통일하되 실제 발표시각을 새로 주장하지 않는다.

**예측 실패·신뢰도.** 저장된 EUMED_H28 후향 평가 11사양×80원점=880행 중 `actual_available===true`만 사용한다. Ridge MAE는 14.34871942(100×로그변화), 방향 적중은 73.75%다. 큰 오차 사례는 실제값과 예측값을 내부 화면에서 비교하며 변화폭을 놓친 정도를 보여준다. 방향 적중만으로 정확한 변화폭이라고 말할 수 없다. 구간 유효 n56, 경험적 포함 89.2857%, 평균 폭 51.5125를 함께 보여준다.

Ridge의 Naive 대비 평균 MAE 감소 약12.80%는 기존 HAC/Holm p=0.323686의 비유의 판정과 구분한다. 겹치는 목표창·사후 보정·실제4발표 n63에서 ETS/Ridge 순위 반전도 유지한다. 전체파일 미실현184행과 이 대상·탐색기간의 제외110행을 구분한다. 과거68/62개 원행과80.9%를 새로 복구하거나 혼합하지 않았다.

## 7. 검증과 실제 수정

작성자 최종 검사는 코드16개, 실자료26개, 실제 Chrome26개가 통과했다. 1920×1080·1600×900·1366×768에서 네 영역씩12장을 생성했다. 최종 브라우저 실행은71.2초였으며 UTC/서울7개 시간 차트 픽셀 비교, 주간41곳 실제 관측값 표시도 포함한다. 공개 Git만 새 폴더에 추출해 실자료 없이 npm ci·코드 검사·빌드를 통과했다.

초기 독립 검수는 실패를 발견했다. 화면 이동 시 스크롤 착지, 미배정 사유, 음수 개선 문구, 점검 질문, 일별 커서, 1회 관측0% 표시,184/110 분모를 고쳤다. 후속 Editor가 시간축 하루 밀림과 관측 없는 주간 커서도 발견해 UTC 기준과 실제 관측일 스냅으로 수정했다. 휴일 화요일 발표를 월요일로 고치지 않고 테스트의 잘못된 가정을 교정했다. 과거 실패·판본·재검수 근거는 `qa/v2/CORRECTION_LOG.md`에 보존한다.

Vera는 독립 산식807,278건 불일치0·최종 화면265건 실패0을 확인하고 지정 앱 범위 PASS_WITH_LIMITATIONS, Editor는 설명·흐름·검수한 화면 범위 PASS로 판정했다. 필수 잔여0이다. 별도 시간검사4,959건 중71건은 검사좌표/표본 한계와 비차단 차이로 분류돼 전체PASS로 합산하지 않는다. 변화율 모드 그림영역 약6px 차이로 인접 날짜가 선택되는 경우 등은 남는다. 상세 독립 판정은 `C_V2_INDEPENDENT_QA.md`와 `C_V2_FINAL_QA_STATUS.md`를 따른다. 원연구는 제품 완성과 별도로 `CONDITIONAL_REVIEW`다. 검사 수만으로 전체 앱·모든 미래 입력·접근성의 무결함을 주장하지 않는다.

## 8. 시각 품질과 개선의 한계

메뉴6→4, 시장 KPI4→3으로 줄이고 같은 기간 재선택과 반복 차트를 줄였다. 차트 수보다 공통 기준의 차이, 실제 A/B 환경, 실패 사례가 먼저 보이게 했다. 그래프의 날짜·단위·관측창과 설명을 연결한 것이 핵심 개선이다. 기본 화면의 설명이 늘어 첫 그래프가 더 아래로 이동한 교환관계는 남는다.

Editor는 최신12장과 별도 브라우저 조작, 네 시간대의7개 차트를 검토했다. Kit의 전후 비교는 최초 뷰·연락판·주요 상단 범위다. 모든 전후 화면을 모든 조합으로 확대 검토했다고 주장하지 않는다. 작은 보조 글자, 중복 안내, A=B 설명 등 비차단 개선 여지는 남는다. console.error0건은 작성자 실행 조건의 결과이며, Editor의 Vite 새 탭에서 favicon404가 있었다. 내부 오프라인 서버는 이 요청을204로 처리해 재실행했다.

## 9. 파일·팀 영향·Git

변경 파일 전체는 Git `49e13b5..HEAD`로 확인한다. 추가한 주요 파일은 계산/달력/상태·공통 시계열·네 페이지·회귀 테스트·방법/통합 문서다. 삭제한 제품 테스트는 이전6메뉴 전용 spec이다. 모든 변경은 C 모듈 안이며 팀원의 A/B·DB·전처리·기존 공통 파일은 불변이다. 기능·시간축·오프라인·문서를 구분해 커밋한다.

기존 [Draft PR #2](https://github.com/hyemin138/corp-analysis-web/pull/2)를 같은 브랜치에서 갱신한다. 실제 push/PR 상태는 인계 로그와 최종 상태표를 확인한다. main push·병합·자동병합·운영 배포는 하지 않는다.

## 10. 실행·인계와 남은 일

현재 프로덕션 미리보기는 http://127.0.0.1:4174/ 이다. 내부 ZIP은 `py -3.13 -B scripts/serve_dist.py`로 http://127.0.0.1:4194/ 에서 실행한다. 소스 개발은 npm ci 후 npm run dev, http://127.0.0.1:5174/ 이다.

ZIP에는 소스·테스트·문서·동결 빌드·자료 한 사본·QA를 포함하고 node_modules·가상환경·개인설정·원마스터·Git 작업트리·인증정보는 제외한다. 파일별 SHA와 전체 CRC, 별도 추출본의 실제 브라우저 실행 결과는 외부 `TAEWOONG_C_DASHBOARD_V2_FINAL_VERIFICATION.json`과 `.zip.sha256`에 기록한다. ZIP 자신의 해시를 내부 보고서에 넣는 순환은 만들지 않는다.

미구현: 신규 예측 생성, 실시간 수집, 팀 DB/API·라우터·인증·운영 배포, 모바일 전용 UI, 접근성 전수, PNG 실제 저장 검증. 공개 빈티지와 일부 연구 판본 조건도 남는다. C의 요청한 다섯 분석은 구현했지만 전체 팀 서비스가 완성됐다는 뜻은 아니다.

팀은 데이터 공급 어댑터·공통 CSS/라우터·인증·최신성 정책을 결정하고 실제 API 회귀를 수행해야 한다. 데이터·연구 의미를 먼저 합의하고 화면을 연결한다. 시연은 **관찰 → 항로 차이 → 통항환경 → 같은 상태의 차이 → 예측 실패와 한계 → 점검 질문** 순서로 진행한다.
